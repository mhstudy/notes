## 第1章 大数据概述 ⭐

### 1.1 什么是大数据

大数据是指**无法在一定时间范围内**用常规软件工具进行捕捉、管理和处理的数据集合。

### 1.2 大数据特征（4V）🔥

| 特征 | 英文 | 说明 |
|:---|:---|:---|
| **Volume** | 大量 | PB、EB 级别数据量 |
| **Velocity** | 高速 | 数据增长速度快，处理要求时效性 |
| **Variety** | 多样 | 结构化、半结构化、非结构化 |
| **Value** | 低价值密度 | 海量数据中有价值的信息占比低 |

### 1.3 大数据技术生态 🔥

```
数据采集层：Flume、Kafka、Maxwell、FlinkCDC
         ↓
数据存储层：HDFS、HBase、Redis、Kafka
         ↓
数据计算层：
  - 离线计算：MapReduce、Spark、Hive、Tez
  - 实时计算：Flink、Spark Streaming
  - OLAP：ClickHouse、Doris
         ↓
数据调度层：DolphinScheduler、Azkaban、Airflow
         ↓
数据应用层：数据可视化、数据挖掘、AI/ML
```

### 1.4 数仓分层架构 🔥🔥

```
ODS（原始数据层）     ← 原始日志和业务数据
  ↓
DWD（明细数据层）     ← 清洗、转换、脱敏
  ↓
DWS（服务数据层）     ← 轻度汇总
  ↓
ADS（应用数据层）     ← 统计指标，供报表使用
```

| 分层 | 英文 | 说明 |
|:---|:---|:---|
| ODS | Operational Data Store | 原始数据，不做处理 |
| DWD | Data Warehouse Detail | 明细层，ETL 清洗 |
| DIM | Dimension | 维度表（用户、商品等） |
| DWS | Data Warehouse Summary | 轻度汇总 |
| ADS | Application Data Store | 应用层，最终指标 |

## 第2章 Hadoop 生态圈 ⭐

### 2.1 核心组件

| 组件 | 作用 | 类比 |
|:---|:---|:---|
| **HDFS** | 分布式文件系统 | 超大硬盘 |
| **YARN** | 资源调度 | 操作系统 |
| **MapReduce** | 分布式计算框架 | 程序运行 |

### 2.2 生态组件

| 组件 | 作用 | 说明 |
|:---|:---|:---|
| **Hive** | SQL on Hadoop | SQL → MR/Spark/Tez |
| **HBase** | NoSQL 数据库 | 海量数据随机读写 |
| **ZooKeeper** | 分布式协调 | 选主、配置管理、分布式锁 |
| **Flume** | 日志采集 | Agent → Channel → Sink |
| **Kafka** | 消息队列 | 高吞吐、持久化 |
| **Spark** | 内存计算引擎 | 比 MR 快 10~100 倍 |
| **Flink** | 流批一体引擎 | 真正的流式处理 |

### 2.3 技术选型参考 🔥

```
场景              推荐方案
─────────────────────────────────────────
离线数仓          Hive + Spark on YARN
实时数仓          Flink + Kafka + Doris
日志采集          Flume → Kafka
业务数据采集      Maxwell/FlinkCDC → Kafka
OLAP 分析         Doris / ClickHouse
任务调度          DolphinScheduler
数据同步          DataX（离线）/ FlinkCDC（实时）
```

## 第4章 数仓建设方法论 🔥🔥

### 4.1 维度建模

| 建模方法 | 说明 | 代表 |
|:---|:---|:---|
| **星型模型** 🔥 | 一个事实表 + 多个维度表 | Kimball 方法论 |
| **雪花模型** | 维度表进一步规范化拆分 | 查询复杂但空间省 |
| **星座模型** | 多个事实表共享维度表 | 大型数仓 |

### 4.2 事实表与维度表

```
事实表（Fact Table）: 记录业务事件，包含度量值
  - 订单表: order_id, user_id, sku_id, amount, create_time
  - 支付表: payment_id, order_id, amount, payment_time

维度表（Dimension Table）: 描述业务实体属性
  - 用户维度: user_id, name, age, gender, city
  - 商品维度: sku_id, sku_name, category, brand, price
  - 时间维度: date_id, year, month, day, weekday
```

### 4.3 缓慢变化维（SCD）

| 类型 | 策略 | 说明 |
|:---|:---|:---|
| **SCD1** | 直接覆盖 | 不保留历史 |
| **SCD2** 🔥 | 新增行 + 拉链表 | 保留完整历史，最常用 |
| **SCD3** | 新增列 | 只保留当前和上一次 |

## 第5章 面试要点 🔥🔥

### Q1：什么是数仓分层？为什么要分层？
> 分层：ODS → DWD → DWS → ADS。好处：复用中间结果、降低耦合、便于管理和排错。

### Q2：离线数仓和实时数仓的区别？
> 离线：T+1，Hive + Spark 批处理。实时：秒级延迟，Flink + Kafka 流处理。

### Q3：星型模型和雪花模型的区别？
> 星型模型维度表不做规范化拆分，查询简单高效，空间冗余。雪花模型维度表进一步拆分，减少冗余但 Join 多。**数仓中推荐星型模型**。

### Q4：什么是拉链表？
> 用于记录维度的历史变化（SCD2）。每行记录包含 `start_date` 和 `end_date`，当前有效记录的 `end_date = 9999-99-99`。新数据到来时，闭合旧记录，新增一行。

### Q5：数仓中如何处理数据倾斜？
> 1. 空值随机分配：`COALESCE(key, RAND())` 
> 2. 热点 Key 单独处理（打散再聚合）
> 3. MapJoin 替代 ReduceJoin（小表广播）
> 4. 调整分区数、增大 Reduce 并行度

### Q6：Hadoop、Spark、Flink 怎么选？
> | 场景 | 推荐 |
> |:---|:---|
> | 离线批处理 | **Spark**（内存计算，快） |
> | 实时流处理 | **Flink**（原生流处理，低延迟） |
> | 简单 ETL / 小规模 | **MapReduce**（稳定，资源少） |
