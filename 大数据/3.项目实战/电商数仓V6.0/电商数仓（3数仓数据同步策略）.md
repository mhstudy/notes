# 电商数仓 V6.0 — 数仓数据同步策略

> 本文档为电商数仓 V6.0 项目第三部分：数据同步策略

---

## 第1章 实时数仓同步数据

### 1.1 🔥 实时同步架构

```
MySQL Binlog → Maxwell → Kafka(topic_db)    → Flink → 实时数仓
日志服务器    → Flume  → Kafka(topic_log)    → Flink → 实时数仓
```

实时数仓的数据同步直接从 **Kafka** 消费，无需落地 HDFS。

## 第2章 离线数仓同步数据

### 2.1 🔥 用户行为数据同步

#### 数据通道

```
Kafka(topic_log) → Flume(消费端) → HDFS(/origin_data/gmall/log/topic_log/yyyy-MM-dd/)
```

#### 🔥 日志消费 Flume 配置（f2.conf）

```properties
# 定义组件
a1.sources = r1
a1.channels = c1
a1.sinks = k1

# Source：Kafka Source
a1.sources.r1.type = org.apache.flume.source.kafka.KafkaSource
a1.sources.r1.kafka.bootstrap.servers = hadoop102:9092,hadoop103:9092
a1.sources.r1.kafka.topics = topic_log
a1.sources.r1.kafka.consumer.group.id = flume_consumer
a1.sources.r1.batchSize = 5000
a1.sources.r1.batchDurationMillis = 2000
# 🔥 拦截器：添加时间戳（用于HDFS按天分区）
a1.sources.r1.interceptors = i1
a1.sources.r1.interceptors.i1.type = com.atguigu.flume.interceptor.TimestampInterceptor$Builder

# Channel：File Channel（保证可靠性）
a1.channels.c1.type = file
a1.channels.c1.checkpointDir = /opt/module/flume/checkpoint/behavior
a1.channels.c1.dataDirs = /opt/module/flume/data/behavior

# Sink：HDFS Sink
a1.sinks.k1.type = hdfs
a1.sinks.k1.hdfs.path = /origin_data/gmall/log/topic_log/%Y-%m-%d
a1.sinks.k1.hdfs.filePrefix = log
a1.sinks.k1.hdfs.round = false
# 🔥 文件滚动策略（避免小文件）
a1.sinks.k1.hdfs.rollInterval = 10       # 10秒滚动
a1.sinks.k1.hdfs.rollSize = 134217728    # 128MB滚动
a1.sinks.k1.hdfs.rollCount = 0           # 不按条数滚动
# 🔥 使用 lzo 压缩 + 文本格式
a1.sinks.k1.hdfs.fileType = CompressedStream
a1.sinks.k1.hdfs.codeC = lzop

# 组装
a1.sources.r1.channels = c1
a1.sinks.k1.channel = c1
```

> 🔥 **关键配置**：`rollSize=128MB` 避免 HDFS 小文件问题，`fileType=CompressedStream` + `codeC=lzop` 压缩存储。

### 2.2 🔥 业务数据同步

#### 数据同步策略

| 策略 | 说明 | 适用表 |
|------|------|--------|
| **🔥 全量同步** | 每天将整张表同步到 HDFS | 维度表（activity_info、base_category、sku_info 等） |
| **🔥 增量同步** | 只同步当天变化的数据 | 事实表（order_info、payment_info 等） |
| **新增及变化** | 同步新增和修改的数据 | user_info、coupon_use |
| **特殊处理** | 全量 + 增量 | cart_info（全量覆盖 + 增量追加） |

#### 🔥 同步策略选择依据

| 判断条件 | 同步策略 |
|----------|----------|
| 数据量小 + 无变化时间字段 | **全量同步** |
| 数据量大 + 有 create_time | **增量同步**（仅新增） |
| 数据量大 + 有 create_time + operate_time | **新增及变化同步** |

### 2.3 🔥 采集通道启停脚本

```bash
#!/bin/bash
# cluster.sh - 一键启停所有采集组件

case $1 in
"start")
    echo "===== 启动 Hadoop 集群 ====="
    ssh hadoop102 "/opt/module/hadoop/sbin/start-dfs.sh"
    ssh hadoop103 "/opt/module/hadoop/sbin/start-yarn.sh"

    echo "===== 启动 Zookeeper 集群 ====="
    for host in hadoop102 hadoop103 hadoop104; do
        ssh $host "/opt/module/zookeeper/bin/zkServer.sh start"
    done

    echo "===== 启动 Kafka 集群 ====="
    for host in hadoop102 hadoop103 hadoop104; do
        ssh $host "/opt/module/kafka/bin/kafka-server-start.sh -daemon /opt/module/kafka/config/server.properties"
    done

    echo "===== 启动 Flume(采集) ====="
    f1.sh start

    echo "===== 启动 Flume(消费) ====="
    f2.sh start

    echo "===== 启动 Maxwell ====="
    maxwell.sh start
;;
"stop")
    echo "===== 停止 Maxwell ====="
    maxwell.sh stop

    echo "===== 停止 Flume(消费) ====="
    f2.sh stop

    echo "===== 停止 Flume(采集) ====="
    f1.sh stop

    echo "===== 停止 Kafka 集群 ====="
    for host in hadoop102 hadoop103 hadoop104; do
        ssh $host "/opt/module/kafka/bin/kafka-server-stop.sh"
    done

    echo "===== 停止 Zookeeper 集群 ====="
    for host in hadoop102 hadoop103 hadoop104; do
        ssh $host "/opt/module/zookeeper/bin/zkServer.sh stop"
    done

    echo "===== 停止 Hadoop 集群 ====="
    ssh hadoop103 "/opt/module/hadoop/sbin/stop-yarn.sh"
    ssh hadoop102 "/opt/module/hadoop/sbin/stop-dfs.sh"
;;
esac
```

## 🔥 面试要点

### Q1：采集通道启停顺序为什么重要？

🔥 **启动顺序**：Hadoop → ZK → Kafka → Flume(采集) → Flume(消费) → Maxwell
- 上游组件必须先于下游启动
- Kafka 依赖 ZK，Flume 依赖 Kafka

🔥 **停止顺序**：与启动相反
- 先停止数据生产者（Maxwell、Flume采集）
- 再停止数据消费者（Flume消费）
- 最后停止基础设施（Kafka、ZK、Hadoop）
