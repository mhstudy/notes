## 第1章 数据仓库概述

### 1.1 🔥 数据仓库分层

```
┌─────────────────────────────────────────────────┐
│                   ADS 层                         │
│            (Application Data Store)              │
│            应用数据层 - 统计指标结果               │
├─────────────────────────────────────────────────┤
│                   DWS 层                         │
│            (Data Warehouse Summary)              │
│            数仓汇总层 - 按主题汇总                 │
├─────────────────────────────────────────────────┤
│                   DWD 层                         │
│            (Data Warehouse Detail)               │
│            数仓明细层 - 清洗、维度退化              │
├─────────────────────────────────────────────────┤
│                   ODS 层                         │
│            (Operational Data Store)              │
│            操作数据层 - 原始数据（保持原貌）         │
├─────────────────────────────────────────────────┤
│                   DIM 层                         │
│            (Dimension)                           │
│            维度层 - 维度表                         │
└─────────────────────────────────────────────────┘
```

| 层级 | 说明 | 存储格式 | 压缩 |
|------|------|---------|------|
| **ODS** | 原始数据，保持数据原貌 | 日志表 JSON / 业务表 JSON | gzip |
| **DIM** | 🔥 维度表（商品、地区、用户、时间等） | ORC | snappy |
| **DWD** | 🔥 事实表（清洗、维度退化） | ORC | snappy |
| **DWS** | 🔥 按主题+粒度汇总（1日/N日/历史） | ORC | snappy |
| **ADS** | 最终统计指标结果 | 无（直接导出MySQL） | - |

## 第2章 数据仓库建模

### 2.1 🔥 维度建模方法论

维度模型由 Ralph Kimball 提出，核心概念：
- **事实表（Fact Table）**：记录业务过程的度量值（如订单金额、支付金额）
- **维度表（Dimension Table）**：描述事实的角度（如谁、什么时间、什么商品）

**建模步骤**：
1. 🔥 **选择业务过程**：下单、支付、退单...
2. 🔥 **声明粒度**：每个订单、每个订单明细、每天每用户...
3. **确认维度**：时间、用户、商品、地区...
4. **确认事实**：订单金额、优惠金额、支付金额...

### 2.2 ⭐ 事实表分类

| 类型 | 说明 | 典型场景 |
|------|------|----------|
| **🔥 事务型事实表** | 记录一次业务事件 | 下单、支付、退单 |
| **⭐ 周期型快照事实表** | 按周期记录状态 | 购物车每日快照 |
| **⭐ 累积型快照事实表** | 记录业务流程各阶段时间 | 订单从下单到支付到发货的时间 |

### 2.3 ⭐ 维度设计要点

- **维度退化**：将低基数维度的属性直接冗余到事实表中
- **拉链表**：记录维度的历史变化（SCD Type 2），使用 `start_date` 和 `end_date`
- 🔥 **缓慢变化维度（SCD）**：
  - Type 0：不变
  - Type 1：覆盖
  - **Type 2（拉链表）**：新增一行记录历史

**数据装载脚本（ods_to_hdfs.sh）：**

```bash
#!/bin/bash
APP=gmall
if [ -n "$1" ]; then
    do_date=$1
else
    do_date=$(date -d '-1 day' +%F)
fi

echo "===== ODS 层数据装载: ${do_date} ====="

# 日志数据加载分区
hive -e "ALTER TABLE ${APP}.ods_log_inc ADD IF NOT EXISTS PARTITION (dt='${do_date}');"

# 业务数据加载分区
load_tables="ods_order_info_inc ods_order_detail_inc ods_payment_info_inc ods_user_info_inc"
for table in $load_tables; do
    hive -e "ALTER TABLE ${APP}.${table} ADD IF NOT EXISTS PARTITION (dt='${do_date}');"
done
```

#### 🔥 用户维度拉链表

```sql
-- 用户维度拉链表
DROP TABLE IF EXISTS dim_user_zip;
CREATE EXTERNAL TABLE dim_user_zip (
    `id`           BIGINT COMMENT '用户ID',
    `name`         STRING COMMENT '用户姓名',
    `phone_num`    STRING COMMENT '手机号（脱敏）',
    `email`        STRING COMMENT '邮箱（脱敏）',
    `user_level`   STRING COMMENT '用户等级',
    `birthday`     STRING COMMENT '生日',
    `gender`       STRING COMMENT '性别',
    `create_time`  STRING COMMENT '创建时间',
    `operate_time` STRING COMMENT '操作时间',
    `start_date`   STRING COMMENT '开始日期',
    `end_date`     STRING COMMENT '结束日期'
) COMMENT '用户维度拉链表'
PARTITIONED BY (`dt` STRING)
STORED AS ORC
LOCATION '/warehouse/gmall/dim/dim_user_zip/'
TBLPROPERTIES ('orc.compress' = 'snappy');
```

**🔥 拉链表更新逻辑：**

```sql
-- 每日更新拉链表
INSERT OVERWRITE TABLE dim_user_zip PARTITION (dt)
-- 新增/变化的用户（当天数据）
SELECT
    id, name, phone_num, email, user_level, birthday, gender,
    create_time, operate_time,
    '${do_date}' AS start_date,
    '9999-12-31' AS end_date,
    '9999-12-31' AS dt
FROM (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY id ORDER BY operate_time DESC) rn
    FROM ods_user_info_inc WHERE dt = '${do_date}' AND type IN ('insert', 'update')
) t WHERE rn = 1
UNION ALL
-- 历史未过期的用户（需要判断是否被更新）
SELECT
    old.id, old.name, old.phone_num, old.email, old.user_level,
    old.birthday, old.gender, old.create_time, old.operate_time,
    old.start_date,
    -- 如果被更新，结束日期改为前一天
    CASE WHEN new.id IS NOT NULL THEN DATE_ADD('${do_date}', -1) ELSE old.end_date END AS end_date,
    CASE WHEN new.id IS NOT NULL THEN DATE_ADD('${do_date}', -1) ELSE old.dt END AS dt
FROM dim_user_zip old
LEFT JOIN (
    SELECT id FROM ods_user_info_inc
    WHERE dt = '${do_date}' AND type IN ('insert', 'update')
    GROUP BY id
) new ON old.id = new.id
WHERE old.dt = '9999-12-31';
```

```sql
-- DWD 层下单事务事实表
INSERT OVERWRITE TABLE dwd_trade_order_detail_inc PARTITION (dt = '${do_date}')
SELECT
    od.id,
    oi.order_id,
    oi.user_id,
    od.sku_id,
    oi.province_id,
    act.activity_id,
    act.activity_rule_id,
    cpn.coupon_id,
    date_format(oi.create_time, 'yyyy-MM-dd') AS date_id,
    oi.create_time,
    od.sku_num,
    od.split_original_amount,
    NVL(act.split_activity_amount, 0.0),
    NVL(cpn.split_coupon_amount, 0.0),
    od.split_total_amount
FROM (
    SELECT data.id, data.order_id, data.sku_id, data.sku_num,
           data.split_original_amount, data.split_total_amount
    FROM ods_order_detail_inc
    WHERE dt = '${do_date}' AND type = 'insert'
) od
JOIN (
    SELECT data.id AS order_id, data.user_id, data.province_id, data.create_time
    FROM ods_order_info_inc
    WHERE dt = '${do_date}' AND type = 'insert'
) oi ON od.order_id = oi.order_id
LEFT JOIN (...) act ON od.id = act.order_detail_id  -- 活动关联
LEFT JOIN (...) cpn ON od.id = cpn.order_detail_id;  -- 优惠券关联
```

## 第6章 数仓开发之 DWS 层

### 6.1 🔥 DWS 层设计

DWS 层按**主题 + 粒度 + 时间范围**进行汇总：

| 汇总表 | 主题 | 粒度 | 时间范围 |
|--------|------|------|----------|
| dws_trade_user_sku_order_1d | 交易 | 用户+商品 | 最近1日 |
| dws_trade_user_order_1d | 🔥 交易 | 用户 | 最近1日 |
| dws_trade_user_cart_add_1d | 交易 | 用户 | 最近1日 |
| dws_trade_user_payment_1d | 交易 | 用户 | 最近1日 |
| dws_trade_province_order_1d | 交易 | 省份 | 最近1日 |
| dws_traffic_session_page_view_1d | 流量 | 会话 | 最近1日 |
| dws_trade_user_order_nd | 交易 | 用户 | 最近N日 |
| dws_trade_user_order_td | 交易 | 用户 | 历史至今 |

#### 🔥 交易域用户粒度订单最近1日汇总表

```sql
INSERT OVERWRITE TABLE dws_trade_user_order_1d PARTITION (dt = '${do_date}')
SELECT
    user_id,
    COUNT(DISTINCT order_id) AS order_count_1d,       -- 下单次数
    SUM(sku_num) AS order_num_1d,                      -- 下单件数
    SUM(split_original_amount) AS order_original_amount_1d,  -- 原始金额
    SUM(NVL(split_activity_amount, 0)) AS activity_reduce_amount_1d,  -- 活动减免
    SUM(NVL(split_coupon_amount, 0)) AS coupon_reduce_amount_1d,      -- 优惠券减免
    SUM(split_total_amount) AS order_total_amount_1d   -- 最终金额
FROM dwd_trade_order_detail_inc
WHERE dt = '${do_date}'
GROUP BY user_id;
```

#### 🔥 用户留存率

```sql
-- 用户留存率指标
INSERT OVERWRITE TABLE ads_user_retention
SELECT * FROM ads_user_retention
UNION
SELECT
    '${do_date}' AS dt,
    login_date_first AS create_date,
    DATEDIFF('${do_date}', login_date_first) AS retention_day,
    SUM(IF(login_date_last = '${do_date}', 1, 0)) AS retention_count,
    COUNT(*) AS new_user_count,
    CAST(SUM(IF(login_date_last = '${do_date}', 1, 0)) / COUNT(*) * 100 AS DECIMAL(16,2)) AS retention_rate
FROM dws_user_user_login_td
WHERE dt = '${do_date}'
    AND login_date_first >= DATE_ADD('${do_date}', -7)
    AND login_date_first < '${do_date}'
GROUP BY login_date_first;
```

## 🔥 面试要点

### Q1：数仓分层的作用？

1. **复杂问题简单化**：每层专注一个职责
2. **减少重复计算**：中间结果复用
3. **统一数据口径**：保证指标一致性
4. **隔离原始数据**：保护原始数据不被修改

### Q2：数仓建模方法论？

- 采用 **维度建模**（Kimball 方法论）
- 🔥 建模步骤：选择业务过程 → 声明粒度 → 确认维度 → 确认事实
- 事实表三种类型：事务型、周期快照型、累积快照型

### Q3：拉链表如何实现？

- 🔥 用 `start_date` 和 `end_date` 标记每条记录的有效时间范围
- 查询当前有效数据：`WHERE end_date = '9999-12-31'`
- 查询历史某天数据：`WHERE start_date <= '2024-01-15' AND end_date >= '2024-01-15'`
- 每日更新：新数据 UNION ALL 历史数据（更新被变更记录的end_date）
