## 第1章 电商业务简介

### 1.1 🔥 电商业务流程

```
用户浏览 → 加入购物车 → 下单 → 支付 → 发货 → 收货 → 评价
                                  ↓
                            退单 → 退款
```

### 1.2 ⭐ 电商常识

| 概念 | 说明 | 举例 |
|------|------|------|
| **SPU** | 标准化产品单元（一类商品） | iPhone 14 |
| **SKU** | 🔥 库存量单元（具体规格的商品） | iPhone 14 128G 蓝色 |
| **平台属性** | 商品的固有属性 | 屏幕尺寸、CPU型号 |
| **销售属性** | 影响用户购买决策的属性 | 颜色、内存大小 |

## 第2章 业务数据介绍

### 2.1 🔥 电商系统表结构

核心业务表（共 36 张）：

| 分类 | 表名 | 说明 | 同步策略 |
|------|------|------|----------|
| **用户** | user_info | 用户基本信息 | 🔥 增量 |
| **用户** | user_address | 用户地址 | 全量 |
| **商品** | sku_info | SKU 信息 | 全量 |
| **商品** | spu_info | SPU 信息 | 全量 |
| **商品** | base_trademark | 品牌表 | 全量 |
| **商品** | base_category1/2/3 | 分类表 | 全量 |
| **交易** | order_info | 🔥 订单主表 | 增量 |
| **交易** | order_detail | 🔥 订单明细表 | 增量 |
| **交易** | order_status_log | 订单状态流水 | 增量 |
| **交易** | payment_info | 支付表 | 增量 |
| **交易** | cart_info | 购物车表 | 全量+增量 |
| **营销** | activity_info | 活动信息 | 全量 |
| **营销** | coupon_info | 优惠券信息 | 全量 |
| **营销** | coupon_use | 优惠券使用 | 增量 |
| **评价** | comment_info | 评论表 | 增量 |
| **收藏** | favor_info | 收藏表 | 增量 |
| **退单** | order_refund_info | 退单表 | 增量 |

> 🔥 **订单表** vs **订单明细表**：订单表是一个订单一条记录；订单明细表是一个订单中每个 SKU 一条记录。如下单买了 3 件商品，order_info 有 1 条，order_detail 有 3 条。

## 第3章 业务数据采集模块

### 3.1 🔥 采集通道

```
MySQL(业务数据) → Maxwell → Kafka(topic_db) → Flume(消费) → HDFS
                                                  或
MySQL(业务数据) → DataX → HDFS（全量同步）
```

### 3.2 ⭐ 采集工具选型

| 工具 | 同步方式 | 原理 | 适用场景 |
|------|---------|------|----------|
| **DataX** | 全量同步 | 直连 MySQL 查询 | 🔥 维度表全量同步 |
| **🔥 Maxwell** | 增量同步 | 监听 MySQL Binlog | 🔥 事实表增量同步 |
| **Canal** | 增量同步 | 监听 MySQL Binlog | 阿里开源，功能丰富 |
| **FlinkCDC** | 增量同步 | 监听 MySQL Binlog | 实时数仓场景 |

### 3.3 🔥 Maxwell 配置

**config.properties：**

```properties
# Maxwell 配置
producer=kafka
kafka.bootstrap.servers=hadoop102:9092,hadoop103:9092,hadoop104:9092
kafka_topic=topic_db

# MySQL 连接配置
host=hadoop102
user=maxwell
password=maxwell
jdbc_options=useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true

# 过滤规则：只监控 gmall 数据库
filter=exclude: *.*, include: gmall.*

# 🔥 输出格式：JSON
# 包含 database, table, type(insert/update/delete), data, old 等字段
```

**Maxwell 输出示例：**

```json
{
  "database": "gmall",
  "table": "order_info",
  "type": "insert",
  "ts": 1674201600,
  "data": {
    "id": 1001,
    "user_id": 100,
    "total_amount": 299.00,
    "order_status": "1001",
    "create_time": "2024-01-20 10:00:00"
  }
}
```

**Maxwell 启停脚本：**

```bash
#!/bin/bash
MAXWELL_HOME=/opt/module/maxwell
case $1 in
"start")
    echo "========== 启动 Maxwell =========="
    $MAXWELL_HOME/bin/maxwell --config $MAXWELL_HOME/config.properties --daemon
;;
"stop")
    echo "========== 停止 Maxwell =========="
    ps -ef | grep maxwell | grep -v grep | awk '{print $2}' | xargs kill -9
;;
esac
```

### 3.4 ⭐ Maxwell 全量同步（Bootstrap）

```bash
# 全量同步 gmall.user_info 表
/opt/module/maxwell/bin/maxwell-bootstrap \
    --database gmall \
    --table user_info \
    --config /opt/module/maxwell/config.properties
```

> 🔥 Bootstrap 输出的 `type` 字段为 `"bootstrap-insert"`，可以在消费端做区分。

## 🔥 面试要点

### Q1：全量同步和增量同步怎么选择？

| 类型 | 同步方式 | 工具 | 适用表 |
|------|---------|------|--------|
| **全量同步** | 每天全量覆盖 | DataX | 🔥 维度表（变化少、数据量小） |
| **增量同步** | 实时捕获变更 | Maxwell | 🔥 事实表（变化频繁、数据量大） |

### Q2：Maxwell 和 Canal 的区别？

| 对比 | Maxwell | Canal |
|------|---------|-------|
| 语言 | Java | Java |
| 输出 | 🔥 JSON（开箱即用） | 原始 Protobuf |
| Bootstrap | ✅ 支持全量同步 | ❌ 不支持 |
| 数据格式 | 统一 JSON | 需要自行解析 |
| 高可用 | 借助 Kafka | 自带 HA |
| 使用复杂度 | 🔥 简单 | 较复杂 |
