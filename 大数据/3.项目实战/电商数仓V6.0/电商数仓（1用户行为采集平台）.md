## 第1章 数据仓库概念

### 1.1 🔥 数据仓库是什么

数据仓库（Data Warehouse）是**为企业制定决策、提供数据支持**的系统。

> 🔥 数据仓库并不是数据的最终目的地，而是为数据最终的目的地做好准备。准备工作包括：**备份、清洗、聚合、统计**等。

**数据来源：**

| 数据类型 | 说明 | 存储方式 |
|----------|------|----------|
| **🔥 业务数据** | 用户交互产生的数据（登录、下单、支付） | MySQL / Oracle |
| **🔥 用户行为数据** | 埋点采集的数据（页面浏览、点击、曝光） | 日志文件 |
| **爬虫数据** | 第三方网站数据 | 文件 |

### 3.4 ⭐ 环境准备

#### 集群分发脚本 xsync

```bash
#!/bin/bash
# 循环遍历所有机器
if [ $# -lt 1 ]; then
    echo "Usage: xsync <file>"
    exit
fi
for host in hadoop102 hadoop103 hadoop104; do
    echo "========== $host =========="
    for file in $@; do
        if [ -e $file ]; then
            pdir=$(cd -P $(dirname $file); pwd)
            fname=$(basename $file)
            ssh $host "mkdir -p $pdir"
            rsync -av $pdir/$fname $host:$pdir
        fi
    done
done
```

#### 集群命令批量执行脚本 xcall

```bash
#!/bin/bash
if [ $# -lt 1 ]; then
    echo "Usage: xcall <command>"
    exit
fi
for host in hadoop102 hadoop103 hadoop104; do
    echo "========== $host =========="
    ssh $host $@
done
```

## 第4章 用户行为数据采集模块

### 4.1 🔥 数据通道

```
日志服务器(hadoop102/103) → Flume(采集) → Kafka(topic_log) → Flume(消费) → HDFS
```

### 4.2 🔥 日志采集 Flume 配置

**Flume 采集端配置（f1.conf）**：

```properties
# 定义组件
a1.sources = r1
a1.channels = c1
a1.sinks = k1

# Source：TailDir Source（断点续传）
a1.sources.r1.type = TAILDIR
a1.sources.r1.filegroups = f1
a1.sources.r1.filegroups.f1 = /opt/module/applog/log/app.*
a1.sources.r1.positionFile = /opt/module/flume/taildir_position.json
# 🔥 自定义拦截器（ETL清洗 + 时间戳提取）
a1.sources.r1.interceptors = i1
a1.sources.r1.interceptors.i1.type = com.atguigu.flume.interceptor.ETLInterceptor$Builder

# Channel：Kafka Channel（直接写入Kafka，省去Sink）
a1.channels.c1.type = org.apache.flume.channel.kafka.KafkaChannel
a1.channels.c1.kafka.bootstrap.servers = hadoop102:9092,hadoop103:9092
a1.channels.c1.kafka.topic = topic_log
a1.channels.c1.parseAsFlumeEvent = false
```

> 🔥 **重点**：使用 **KafkaChannel** 代替 Memory Channel + Kafka Sink，减少一层组件，提高效率和可靠性。

### 4.3 ⭐ Flume 启停脚本

```bash
#!/bin/bash
# f1.sh - Flume采集端启停脚本
case $1 in
"start")
    for host in hadoop102 hadoop103; do
        echo "========== 启动 $host 采集Flume =========="
        ssh $host "nohup /opt/module/flume/bin/flume-ng agent -n a1 -c /opt/module/flume/conf -f /opt/module/flume/job/file_to_kafka.conf >/dev/null 2>&1 &"
    done
;;
"stop")
    for host in hadoop102 hadoop103; do
        echo "========== 停止 $host 采集Flume =========="
        ssh $host "ps -ef | grep file_to_kafka | grep -v grep | awk '{print \$2}' | xargs -n1 kill -9"
    done
;;
esac
```

## 🔥 面试要点

### Q1：为什么选择 Flume + Kafka 的组合？

- **Flume** 擅长日志文件采集（TailDir Source 支持断点续传）
- **Kafka** 擅长数据缓冲和解耦（支持多消费者、高吞吐）
- 🔥 使用 **KafkaChannel** 可以减少一层组件，提高效率

### Q2：数据采集如何保证不丢失？

1. Flume TailDir Source 支持**断点续传**（positionFile）
2. Kafka Channel 保证数据先写入 Kafka 再确认
3. Kafka 自身的**副本机制**保证数据不丢失
4. 消费端 Flume 使用 **HDFS Sink** + File Channel 保证可靠性
